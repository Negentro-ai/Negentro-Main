## Users and sessions serve different purposes

## Recommended scope model

- Use a stable application-level identifier for each user.
- Create or resolve a session identifier for each conversation or workflow.
- Associate requests with the correct tenant or namespace when multi-tenant isolation is required.

## Example identity model

## Data isolation

- Authenticate every request.
- Authorize access to the requested user, session, and tenant.
- Validate scope identifiers on the server.
- Prevent one tenant from querying another tenant's information.
- Apply consistent access rules to retrieval, updates, and deletion.
- Avoid logging secrets or unnecessary personal information.
- Test cross-user and cross-tenant access boundaries.

## Session lifecycle

A typical application can create or resolve a session when a conversation begins, attach relevant events to that session, retrieve session context during the interaction, and apply a retention or cleanup policy when the session ends.

## Privacy and retention

Give users appropriate control over their stored information. Define retention periods, deletion behavior, access policies, and any process for exporting or correcting data where required.
