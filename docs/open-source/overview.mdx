## Default components

Negentro ships with sane, production-ready defaults for each part of the pipeline. Every component can be replaced or explicitly configured to match your existing VPC infrastructure and provider preferences.

| Component | Default | Description |
| :-- | :-- | :-- |
| LLM | OpenAI (via BYOK) | Used for fact extraction and entity summarization. |
| Embeddings | OpenAI text-embedding-3-small | 1536-dimensional dense vector embeddings. |
| Vector store | pgvector | PostgreSQL vector extension with HNSW index. |
| History store | PostgreSQL | Transactional relational store for memory records. |

| Component | Default | Description |
| :-- | :-- | :-- |
| Reranker | UnifiedScorer (BM25 + RRF) | Evaluates 11 signals including vector and trigram text match. |
| Storage | PostgreSQL (Bitemporal KG) | Tracks valid_at real-world validity alongside system time. |
| Metadata cache | Redis | Low-latency session caching and rate limit coordination. |
| Providers | Multi-Provider BYOK Routing | Natively handles OpenAI, Anthropic, Gemini, DeepSeek, and Ollama. |

## Configure your stack

```typescript negentro.config.ts
import { createNegentro } from '@negentro/sdk';

const negentro = createNegentro({
  llm: "openai:gpt-4o",
  embeddings: "openai:text-embedding-3-small",
  // Connect directly to your existing infrastructure
  vectorStore: "pgvector://localhost:5432/negentro",
  storage: "postgres://localhost:5432/negentro_graph",
  cache: "redis://localhost:6379"
});
```

## Build on the open-source stack

- Replace infrastructure components (e.g., swap Redis for an alternative caching layer or SQLite for embedded use).
- Configure multi-provider routing and failover logic to prevent LLM downtime.
- Integrate directly with your existing enterprise PostgreSQL databases without migrating schemas.
- Build custom Active Inference workflows and agent MCP tools with private model access.
